# 면접 Q&A 정리본 (한국어)

# 1. 자료구조

## Array & Linked List

### Q. Array는 어떤 자료구조 인가요?
> Array는 연관된 데이터를 메모리상에 연속적이고 순차적으로 저장하는 자료구조입니다. 보통 미리 정해진 크기만큼 공간을 할당받고, 인덱스를 통해 빠르게 접근할 수 있습니다.

- 꼬리 질문: 미리 예상한 것보다 더 많은 수의 data를 저장하느라 Array의 size를 넘어서게 됐습니다. 이 때, 어떻게 해결할 수 있을까요?
  > 더 큰 배열을 새로 만들고 기존 데이터를 모두 옮긴 뒤, 기존 배열을 버리는 방식으로 해결할 수 있습니다. 이런 방식이 Dynamic Array의 기본 아이디어입니다. 데이터 크기를 예측하기 어렵다면 처음부터 Linked List를 고려할 수도 있습니다.

### Q. Dynamic Array는 어떤 자료구조 인가요?
> Dynamic Array는 고정 크기 배열의 한계를 보완한 자료구조입니다. 공간이 가득 차면 더 큰 배열을 새로 만들고 기존 데이터를 옮겨서 크기를 유동적으로 늘릴 수 있습니다.

- 꼬리 질문: Dynamic Array를 Linked List와 비교하여 장단점을 설명해 주세요.
  > Dynamic Array는 인덱스 접근이 빨라서 조회가 `O(1)`이고, 맨 뒤에 데이터를 추가하거나 삭제하는 것도 빠릅니다. 반면 중간 삽입이나 삭제는 뒤 원소를 밀어야 해서 느리고, resize 시 일시적으로 큰 비용이 듭니다. Linked List는 크기 예측이 필요 없고 삽입/삭제에 유리하지만, 임의 접근은 느립니다.

### Q. Linked List에 대해서 설명해 주세요.
> Linked List는 각 노드가 데이터와 다음 노드의 주소를 저장하는 자료구조입니다. 물리적인 메모리상에서는 연속적이지 않지만, 각 노드가 다음 노드를 가리켜 논리적인 연속성을 유지합니다.

### Q. Array vs Linked List를 비교해서 설명해주세요
> Array는 메모리상에 연속적으로 저장되고, Linked List는 비연속적으로 저장되지만 포인터로 연결됩니다. 그래서 Array는 조회가 빠르고 `O(1)` 인덱스 접근이 가능하지만, 중간 삽입/삭제는 `O(n)`입니다. Linked List는 삽입/삭제 자체는 포인터만 바꾸면 되지만, 원하는 위치까지 가는 데 시간이 걸려 조회가 느립니다.

- 꼬리 질문: 어느 상황에 Linked List를 쓰는게 Array보다 더 나을까요?
  > 삽입과 삭제가 자주 일어나고, 저장할 데이터 개수를 미리 예측하기 어렵고, 조회 빈도가 낮을 때 Linked List가 더 유리합니다.

- 꼬리 질문: 어느 상황에 Array를 쓰는게 Linked List보다 더 나을까요?
  > 조회가 많고, 데이터 개수를 어느 정도 예측할 수 있고, 반복문으로 빠르게 순회해야 할 때 Array가 더 좋습니다. 메모리 사용량도 포인터가 없는 만큼 더 효율적일 수 있습니다.

- 꼬리 질문: Array와 Linked List의 memory allocation은 언제 일어나며, 메모리의 어느 영역을 할당 받나요?
  > 일반적인 정적 배열은 선언 시점에 메모리가 잡히고 보통 스택 영역에 놓일 수 있습니다. 반면 Linked List는 실행 중 노드를 만들 때마다 동적으로 메모리를 할당하며, 보통 힙 영역을 사용합니다.

## Queue & Stack

### Q. Queue는 무슨 자료구조 인가요?
> Queue는 먼저 들어온 데이터가 먼저 나가는 FIFO 구조의 자료구조입니다. 대표적으로 `enqueue`, `dequeue` 연산을 제공하고, BFS나 작업 대기열 같은 곳에 많이 쓰입니다.

- 꼬리 질문: Array-Base 와 List-Base의 경우 어떤 차이가 있나요?
  > Array 기반 Queue는 보통 원형 큐로 구현해서 메모리를 효율적으로 사용합니다. 다만 공간이 부족해지면 resize가 필요할 수 있습니다. Linked List 기반 Queue는 앞뒤 포인터만 관리하면 고정 크기 없이 유연하게 확장할 수 있습니다.

### Q. Stack은 어떤 자료구조 인가요?
> Stack은 가장 나중에 들어온 데이터가 가장 먼저 나가는 LIFO 구조의 자료구조입니다. 함수 호출, DFS, 괄호 검사, 뒤로 가기 같은 기능에 자주 사용됩니다.

### Q. Stack 두 개를 이용하여 Queue를 구현해 보세요
> 하나의 스택은 입력용, 다른 하나의 스택은 출력용으로 사용하면 됩니다. 입력은 첫 번째 스택에 push하고, 출력 시 두 번째 스택이 비어 있으면 첫 번째 스택의 원소를 모두 옮긴 뒤 pop 하면 FIFO처럼 동작합니다.

- 꼬리 질문: 시간복잡도는 어떻게 되는지 설명해 주세요.
  > `enqueue`는 보통 `O(1)`입니다. `dequeue`는 두 번째 스택이 비어 있으면 원소를 모두 옮겨야 해서 최악의 경우 `O(n)`이지만, 전체적으로 보면 분할상환 기준으로는 효율적으로 동작합니다.

### Q. Queue 두 개를 이용하여 Stack을 구현해 보세요
> 한 큐에 데이터를 계속 넣고, pop이 필요할 때 마지막 원소 하나만 남길 때까지 다른 큐로 옮기면 됩니다. 남은 마지막 원소를 꺼내면 LIFO처럼 동작합니다.

- 꼬리 질문: 시간복잡도는 어떻게 되는지 설명해 주세요.
  > `push`는 큐에 한 번 넣으면 되므로 `O(1)`입니다. `pop`은 마지막 원소만 남기기 위해 대부분의 데이터를 옮겨야 하므로 `O(n)`입니다.

### Q. Queue vs Priority Queue를 비교하여 설명해 주세요
> 일반 Queue는 들어온 순서대로 처리하는 FIFO 구조입니다. 반면 Priority Queue는 입력 순서와 상관없이 우선순위가 높은 데이터가 먼저 나옵니다. 보통 Queue는 `O(1)` 연산이 많고, Priority Queue는 힙 기반으로 `O(log n)` 연산을 가집니다.

## Hash table & BST

### Q. BST는 어떤 자료구조 인가요?
> BST는 이진 탐색 트리로, 각 노드의 왼쪽 서브트리에는 더 작은 값, 오른쪽 서브트리에는 더 큰 값이 오는 구조입니다. 균형이 잘 맞으면 탐색, 삽입, 삭제가 `O(log n)`이지만, 한쪽으로 치우치면 `O(n)`까지 나빠질 수 있습니다.

- 꼬리 질문: 이진트리(Binary tree)는 어떤 자료구조 인가요?
  > 모든 노드의 자식 수가 최대 2개인 트리를 이진트리라고 합니다.

- 꼬리 질문: BST의 worst case 시간복잡도는 `O(n)`입니다. 어떠한 경우에 worst case가 발생하나요?
  > 값이 한쪽으로만 계속 들어가서 트리가 편향되면 연결 리스트처럼 됩니다. 이런 경우 탐색도 `O(log n)`이 아니라 `O(n)`이 됩니다.

- 꼬리 질문: 해결방법은 무엇인가요?
  > AVL 트리나 Red-Black Tree 같은 자가 균형 이진 탐색 트리를 사용하면 높이를 일정하게 유지할 수 있습니다.

### Q. Hash table는 어떤 자료구조 인가요?
> Hash Table은 key를 hash function에 넣어 나온 해시값을 위치로 사용해 key-value를 저장하는 자료구조입니다. 평균적으로 조회, 삽입, 삭제가 `O(1)`에 가깝습니다.

- 꼬리 질문: 좋은 hash function의 조건은 뭘까요?
  > 계산이 빠르고, 해시값이 특정 구간에 몰리지 않도록 고르게 분포하는 것이 중요합니다.

### Q. Hash table에서 collision이 발생하면 어떻게 되나요? 해결방법엔 뭐가 있을까요?
> 서로 다른 key가 같은 해시값을 가지면 collision이 발생합니다. 대표적인 해결 방법은 open addressing과 separate chaining입니다.

- 꼬리 질문: worst case의 시간복잡도는 `O(n)`이라고 했는데 어떤 상황인가요?
  > 모든 key가 같은 해시값을 가지면 결국 한 버킷이나 한 체인에 모두 몰리게 됩니다. 이 경우 선형 탐색처럼 동작해서 `O(n)`이 됩니다.

- 꼬리 질문: 이중해싱(double hashing)이 무엇인지 설명해 주세요.
  > open addressing에서 충돌이 났을 때 두 번째 해시 함수를 사용해 탐사 간격을 정하는 방식입니다. 클러스터링을 줄이는 데 도움이 됩니다.

# 2. 운영체제 (OS)

## Process & Thread

### Q. process를 간단히 설명해 주세요.
> Process는 실행 파일이 메모리에 적재되고 CPU를 할당받아 실제로 실행 중인 상태를 의미합니다.

- 꼬리 질문: process의 memory 영역(code, data, stack, heap)에 대해서 설명해 주세요.
  > Code 영역은 실행 코드, Data 영역은 전역 변수와 static 변수, Stack 영역은 지역 변수와 함수 호출 정보, Heap 영역은 동적 할당 메모리를 저장합니다.

### Q. Multi process에 대해서 설명해 주세요.
> Multi process는 두 개 이상의 process가 동시에 실행되는 구조입니다. CPU 코어가 하나면 시분할로 번갈아 실행되고, 여러 코어면 병렬로 실행될 수 있습니다.

- 꼬리 질문: process의 context는 무엇인가요?
  > Process의 현재 실행 상태를 나타내는 정보입니다. 예를 들어 레지스터 값, PC, 상태 정보 등이 포함됩니다.

- 꼬리 질문: PCB(Process Control Block)에 저장되는 것들은 무엇이 있나요?
  > Process 번호, 상태, 프로그램 카운터, 레지스터, 스케줄링 정보, 메모리 정보 같은 운영체제가 필요한 관리 정보가 들어갑니다.

- 꼬리 질문: Context switch에 대해서 설명해 주세요.
  > CPU가 한 process에서 다른 process로 넘어갈 때 기존 상태를 저장하고 새 상태를 복원하는 과정입니다.

- 꼬리 질문: process의 state에는 어떤 것들이 있나요?
  > 대표적으로 running, ready, blocked 상태가 있습니다. CPU를 사용 중인지, 대기 중인지, I/O 등으로 막혀 있는지를 구분합니다.

### Q. Multi thread에 대해서 설명해 주세요.
> Thread는 하나의 process 안에서 실행되는 작업 흐름 단위입니다. 여러 thread는 같은 process의 code, data, heap을 공유하고, stack은 각각 따로 가집니다.

- 꼬리 질문: thread는 왜 독립적인 stack memory 영역이 필요한가요?
  > 함수 호출 정보, 지역 변수, 리턴 주소는 thread마다 독립적으로 관리되어야 하기 때문입니다.

- 꼬리 질문: process와 thread를 비교설명 해주세요.
  > Process는 자원을 할당받는 단위이고, Thread는 그 자원을 실제로 사용하는 실행 단위입니다. Process는 서로 독립적이고, Thread는 같은 process 안에서 자원을 공유합니다.

### Q. multi process와 multi thread를 비교설명해 주세요.
> Multi thread는 메모리와 자원을 더 적게 쓰고 context switching도 더 빠릅니다. 반면 자원을 공유하므로 동기화 문제가 있고, 하나의 thread 장애가 전체 process에 영향을 줄 수 있습니다. Multi process는 비용이 더 크지만 안정성이 높습니다.

- 꼬리 질문: multi thread가 multi process보다 좋은 점은 무엇인가요?
  > 메모리 사용량이 적고, process 생성 비용이 없거나 적고, thread 간 통신이 IPC보다 훨씬 가볍습니다.

- 꼬리 질문: multi thread가 multi process보다 안좋은 점은 무엇인가요?
  > 자원 공유 때문에 동기화가 어렵고, 한 thread 문제로 같은 process의 다른 thread도 영향을 받을 수 있습니다.

### Q. multi process환경에서 process간에 데이터를 어떻게 주고 받을까요?
> Process는 서로 독립된 주소 공간을 가지기 때문에 기본적으로 직접 메모리를 공유하지 못합니다. 그래서 IPC를 통해 데이터를 주고받습니다.

- 꼬리 질문: IPC의 예시를 들어주실 수 있나요?
  > 공유 메모리, 파이프, 소켓, 메시지 큐 등이 대표적입니다.

- 꼬리 질문: 공유메모리와 메시지 전달 모델의 장단점을 설명해 주세요.
  > 공유 메모리는 kernel 개입이 적어서 빠르지만 동기화 책임이 애플리케이션에 있습니다. 메시지 전달은 느릴 수 있지만 구현이 단순하고 비교적 안전합니다.

### Q. Multi process/thread 환경에서 동기화 문제를 어떻게 해결하나요?
> 여러 실행 흐름이 같은 자원을 동시에 건드리면 race condition이 생길 수 있습니다. 이를 막기 위해 임계영역을 보호하고, mutex나 semaphore 같은 동기화 기법을 사용합니다.

- 꼬리 질문: mutex와 semaphore 기법을 비교 설명해 주세요.
  > Mutex는 한 번에 하나의 thread만 자원에 접근하게 합니다. Semaphore는 정해진 개수만큼 동시에 접근할 수 있게 허용합니다.

### Q. 교착상태(Deadlock)에 대해서 간단히 설명해 주세요.
> Deadlock은 두 개 이상의 thread나 process가 서로 상대가 가진 자원을 기다리면서 무한 대기에 빠지는 상황입니다.

- 꼬리 질문: deadlock은 언제 발생하게 되나요?
  > 상호 배제, 점유 대기, 비선점, 순환 대기라는 네 가지 조건이 동시에 만족될 때 발생할 수 있습니다.

## Memory

### Q. paging이란 뭔가요?
> Paging은 process의 논리 주소 공간을 일정한 크기의 page로 나누고, 이를 물리 메모리의 frame에 나누어 적재하는 메모리 관리 기법입니다.

- 꼬리 질문: paging 기법 사용시 발생할 수 있는 메모리 단편화 문제에 대해 설명하시오
  > Paging은 외부 단편화는 줄이지만, 마지막 page가 꽉 차지 않을 수 있어 내부 단편화가 발생할 수 있습니다.

### Q. segmentation에 대해서 설명해 주세요.
> Segmentation은 process의 메모리 공간을 code, data, stack처럼 의미 단위의 segment로 나누어 관리하는 기법입니다.

- 꼬리 질문: segmentation의 메모리 단편화 문제에 대해 설명해 주세요.
  > Segmentation은 segment 크기만큼 정확히 할당하므로 내부 단편화는 적지만, 외부 단편화가 발생할 수 있습니다.

- 꼬리 질문: paging과 segmentation의 차이는 뭔가요?
  > Paging은 고정 크기 page 단위, Segmentation은 의미 단위 segment 기반입니다. Paging은 내부 단편화, Segmentation은 외부 단편화 문제가 더 큽니다.

- 꼬리 질문: paged segmentation 기법에 대해 설명하시오
  > Segmentation을 기본으로 하되 각 segment를 다시 page 단위로 나누는 방식입니다. Segmentation의 의미 단위 장점과 Paging의 외부 단편화 완화 효과를 함께 가져가려는 방식입니다.

### Q. 가상 메모리에 대해서 설명해 주세요.
> 가상 메모리는 process 전체가 물리 메모리에 다 올라오지 않아도 실행될 수 있게 해주는 기법입니다. 이를 통해 실제 메모리보다 큰 프로그램도 실행할 수 있습니다.

- 꼬리 질문: 요구페이징(demand paging)이란 무엇인가요?
  > 실제로 필요한 page가 접근될 때만 메모리에 적재하는 방식입니다. 메모리 사용량과 초기 적재 비용을 줄일 수 있습니다.

- 꼬리 질문: 페이지 교체 알고리즘(replacement algorithm)을 아는대로 말씀해주세요.
  > FIFO, 최적 교체, LRU, LFU 등이 있습니다.

- 꼬리 질문: LRU알고리즘과 LFU 알고리즘을 비교 설명해 주세요.
  > LRU는 가장 오래 참조되지 않은 page를 교체하고, LFU는 참조 횟수가 가장 적은 page를 교체합니다.

# 3. 데이터베이스

## DB 구조 & 설계

### Q. Primary key가 무엇인지 설명해 주세요.
> Primary Key는 각 row를 유일하게 식별하는 key입니다. null을 가질 수 없고, 중복도 허용되지 않습니다.

- 꼬리 질문: Primary Key와 Foreign Key에 대해 설명해 주세요.
  > Primary Key는 테이블 내부에서 row를 유일하게 식별하는 key이고, Foreign Key는 다른 테이블의 Primary Key를 참조하는 column입니다.

- 꼬리 질문: Candidate key에 대해 설명하시오
  > Candidate Key는 유일성과 최소성을 만족해서 Primary Key 후보가 될 수 있는 key입니다.

- 꼬리 질문: alternate key에 대해 설명하시오.
  > Primary Key로 선택되지 않은 나머지 Candidate Key를 Alternate Key라고 합니다.

- 꼬리 질문: composite key에 대해 설명하시오
  > 두 개 이상의 column을 조합해 row를 유일하게 식별하는 key입니다.

### Q. 관계형 데이터베이스의 N:M 관계에 대해서 설명해 주세요.
> 양쪽 엔티티가 서로 여러 개와 연결될 수 있는 관계입니다. 보통 중간 테이블을 두어 1:N, N:1 관계 두 개로 풀어서 표현합니다.

- 꼬리 질문: 1:N 관계에 대해서 설명해 주세요.
  > 한 엔티티의 하나의 row가 다른 엔티티의 여러 row와 연결될 수 있는 관계입니다.

### Q. left outer join, inner join 차이를 설명해 주세요
> Inner Join은 양쪽 테이블에 모두 존재하는 데이터만 반환합니다. Left Outer Join은 왼쪽 테이블의 모든 행을 기준으로 하고, 오른쪽에 매칭이 없으면 null을 채웁니다.

### Q. RDB - NoSQL를 비교 설명해 주세요.
> RDB는 정해진 schema를 가진 테이블 기반 구조이고, NoSQL은 더 유연한 비정형 데이터 저장에 적합합니다. RDB는 강한 정합성과 update에 유리하고, NoSQL은 scale-out과 대규모 조회 처리에 유리한 경우가 많습니다.

- 꼬리 질문: NoSQL은 언제 사용하면 좋을까요?
  > 데이터 구조가 자주 바뀌거나, update보다 조회가 많고, 대용량 확장이 중요한 경우에 적합합니다.

- 꼬리 질문: RDB는 언제 사용하면 좋을까요?
  > 구조가 명확하고 정합성이 중요하며, update가 자주 일어나는 시스템에 적합합니다.

## Transaction

### Q. Transaction을 간단히 설명해 주세요.
> Transaction은 DB 작업의 최소 단위입니다. 하나 이상의 query를 묶어서 모두 성공하거나 모두 실패하게 처리하며, ACID 성질을 만족해야 합니다.

- 꼬리 질문: COMMIT과 ROLLBACK에 대해 설명해보세요.
  > COMMIT은 변경 사항을 최종 반영하는 것이고, ROLLBACK은 작업 중 오류가 발생했을 때 이전 상태로 되돌리는 것입니다.

- 꼬리 질문: 원자성(일관성, 고립성, 지속성)이 뭔가요?
  > 원자성은 전부 수행되거나 전부 수행되지 않는 성질입니다. 일관성은 제약을 깨지 않는 것, 고립성은 서로 간섭하지 않는 것, 지속성은 커밋 후 장애가 나도 결과가 유지되는 것입니다.

### Q. DeadLock이란 무엇인지 설명해 주세요.
> DB deadlock은 여러 transaction이 서로가 가진 lock을 기다리다가 영원히 대기하는 상황입니다.

- 꼬리 질문: deadlock을 해결하려면 어떻게 해야 하나요?
  > 예방, 회피, 탐지-회복 같은 방법이 있고, 실무에서는 락 순서를 맞추고 트랜잭션을 짧게 유지하는 방식이 중요합니다.

## Index

### Q. Index가 왜 필요한가요?
> Index는 테이블 검색 성능을 높이기 위한 자료구조입니다. 전체 테이블을 다 읽지 않고도 조건에 맞는 데이터 위치를 빠르게 찾을 수 있습니다.

- 꼬리 질문: SELECT의 성능을 높일 수 있는 방법은 뭐가 있을까요?
  > 대표적으로 적절한 index를 사용하면 WHERE 조건 검색 속도를 크게 높일 수 있습니다.

- 꼬리 질문: index의 내부동작은 어떻게 동작하나요
  > 일반적인 RDBMS는 B+Tree 기반 index를 사용해 조건에 맞는 데이터 위치를 빠르게 찾습니다.

- 꼬리 질문: index를 많이 생성하면 안되나요?
  > 조회 성능은 좋아질 수 있지만, 저장 공간이 늘고 insert/update/delete 때 index도 같이 갱신해야 하므로 오히려 성능이 나빠질 수 있습니다.

### Q. index를 어느 column에 사용하는 것이 좋을까요?
> WHERE 절에 자주 등장하고, 수정은 적고, 카디널리티가 높고, 선택도가 좋은 column이 index 대상에 적합합니다.

- 꼬리 질문: index를 쓰면 성능이 좋아지니까 모든 컬럼에 인덱스를 사용하면 성능이 더 좋겠네요?
  > 그렇지 않습니다. 모든 index는 유지 비용이 있고, 쓰기 성능과 저장 공간에 부담을 줍니다.

- 꼬리 질문: 우리 회사의 고객 DB에서 성별 column에 index를 걸어주는게 좋을까요?
  > 보통 좋지 않습니다. 성별은 값 종류가 적어서 카디널리티가 낮고, index 효율이 거의 없습니다.

- 꼬리 질문: true 또는 false 값을 갖는 column에서, true 1%, false 99%의 비율로 구성된 상황에서는 index를 거는게 좋을까요?
  > 일반적으로도 권장되지 않습니다. 값 종류 자체가 매우 적어서 index 효율이 낮습니다.

### Q. 데이터를 검색을 할 때 hash table의 시간복잡도는 O(1)이고 b+tree는 O(logn)으로 더 느린데 왜 index는 hash table이 아니라 b+tree로 구현되나요?
> Hash Table은 단건 조회는 빠르지만 정렬이 안 되어 있어서 범위 검색에 매우 약합니다. 반면 B+Tree는 정렬된 구조라 부등호 조건이나 범위 조건을 효율적으로 처리할 수 있어서 DB index에 더 적합합니다.

# 4. 네트워크

## TCP/IP

### Q. OSI 7계층과 TCP/IP 4계층을 비교하여 설명해주세요.
> OSI 7계층은 네트워크 통신을 설명하기 위한 표준 모델이고, TCP/IP 4계층은 실제 인터넷에서 더 많이 쓰는 단순화된 모델입니다.

### Q. TCP vs UDP를 비교해서 설명해주세요
> TCP는 연결 지향이고 신뢰성을 보장합니다. UDP는 비연결형이고 빠르지만 순서 보장이나 재전송을 제공하지 않습니다.

### Q. 3-way handshake는 무엇이고 각 과정은 어떻게 되나요?
> TCP 연결을 맺기 전 클라이언트와 서버가 서로 통신 가능 상태를 확인하는 과정입니다. 클라이언트가 SYN을 보내고, 서버가 SYN+ACK를 보내고, 마지막으로 클라이언트가 ACK를 보내면 연결이 성립합니다.

- 꼬리 질문: 그럼 4-way handshake는 뭔가요?
  > TCP 연결을 종료하는 과정입니다. 양방향 연결을 각각 닫아야 해서 보통 네 단계가 필요합니다.

## HTTP

### Q. HTTP가 뭔지 설명해 주세요.
> HTTP는 웹에서 클라이언트와 서버가 request/response 방식으로 정보를 주고받는 프로토콜입니다. TCP/IP 기반이며, 대표적인 특징은 Connectionless와 Stateless입니다.

### Q. HTTP request method 중 GET vs POST를 비교 설명해 주세요.
> GET은 리소스 조회에 사용하고, POST는 데이터 생성이나 처리를 요청할 때 주로 사용합니다. GET은 URL에 파라미터를 담고 캐시와 히스토리에 남을 수 있으며, POST는 body에 데이터를 담고 보통 캐시되지 않습니다.

- 꼬리 질문: HTTP request method 중 PUT vs PATCH를 비교 설명해주세요.
  > PUT은 리소스를 전체 대체하는 데 가깝고, PATCH는 일부 필드만 부분 수정할 때 사용합니다.

### Q. HTTP status code에 대해서 설명해 주세요
> HTTP status code는 요청 결과를 숫자로 표현한 응답 코드입니다. 보통 1xx부터 5xx까지 다섯 클래스가 있고, 성공, 리다이렉션, 클라이언트 오류, 서버 오류 등을 구분합니다.

### Q. www.google.com을 주소창에 쳤을 때 화면이 나오기까지의 과정을 네트워크 관점으로 설명해 주세요.
> 브라우저가 DNS로 서버 IP를 조회하고, TCP 연결을 맺고, HTTP 요청을 보냅니다. 서버가 HTTP 응답을 보내면 브라우저가 이를 받아 렌더링해 화면에 보여줍니다.

## Authorization

### Q. 쿠키와 세션의 차이점을 설명해 주세요
> 쿠키는 브라우저에 저장되는 데이터이고, 세션은 서버 측에 상태를 저장하는 방식입니다. 세션은 보안성은 좋지만 서버 자원을 더 사용합니다.

- 꼬리 질문: 세션이 보안도 좋은데 쿠키를 사용하는 이유는 뭔가요?
  > 서버 자원 부담을 줄이고, 간단한 상태 정보는 클라이언트에 저장하는 것이 더 효율적일 수 있기 때문입니다.

- 꼬리 질문: 쿠키의 사용 예를 아는대로 말씀해주세요
  > 장바구니, 자동 로그인, “오늘 하루 보지 않기” 같은 기능이 대표적입니다.

### Q. 쿠키와 세션을 이용한 로그인 방식을 화이트보드에 설명해 주세요.
> 사용자가 로그인하면 서버는 세션을 만들고 세션 ID를 쿠키로 브라우저에 전달합니다. 이후 브라우저는 요청마다 이 쿠키를 보내고, 서버는 세션 ID를 통해 로그인 상태를 확인합니다.
